# Highrise Discord Bot

## Overview

This is a Discord bot that facilitates trading of Highrise metaverse items through a black market system with user verification. The bot integrates with the Highrise game API to verify user ownership and manages a marketplace for item trading within Discord servers.

## System Architecture

The bot follows a modular architecture with clear separation of concerns:

- **Main Application**: Entry point (`main.py`) that initializes the bot and handles startup/shutdown
- **Command System**: Organized command handlers using Discord.py's cog system
- **Database Layer**: SQLite-based data persistence using aiosqlite for async operations
- **API Integration**: Highrise web API client for user verification and profile data
- **Utility Modules**: Common functions for formatting, validation, and embed creation

The architecture prioritizes async operations throughout to handle Discord's event-driven nature and external API calls efficiently.

## Key Components

### 1. Always-On Keep-Alive System
- **Flask Web Server**: Runs on port 8080 to prevent bot from sleeping
- **Health Endpoints**: `/` and `/health` for uptime monitoring
- **Thread-Based**: Daemon thread ensures clean shutdown
- **24/7 Operation**: Maintains constant Discord connection

### 2. User Verification System
- **Purpose**: Verify Discord users own their claimed Highrise accounts
- **Implementation**: Two-step verification process using Highrise bio validation
- **Security**: 8-character verification codes with 10-minute expiration
- **Database**: User verification status and Highrise profile data storage

### 2. Marketplace System
- **Purpose**: Enable users to list, browse, and purchase Highrise items
- **Features**: Item categorization, pricing, seller contact facilitation
- **Limitations**: Maximum 10 listings per user, price limits (1-1B coins)
- **Transaction Handling**: Logging and history tracking with optional fees

### 3. Database Schema
- **Users Table**: Discord-Highrise account mappings with verification status
- **Market Listings**: Item details, pricing, seller info, and transaction status
- **Verification Codes**: Temporary codes for account verification process
- **Transaction Logs**: Historical data for marketplace activities

### 4. Discord Commands
- Slash commands for all user interactions
- Interactive UI components (buttons, modals, menus)
- Role-based access control for admin functions
- Auto-deleting messages for spam prevention

## Data Flow

1. **User Verification**:
   - User requests verification with Highrise username
   - Bot generates unique code and instructs user to add to Highrise bio
   - Bot validates bio content via Highrise API
   - Verification status stored in database

2. **Marketplace Operations**:
   - Verified users can list items with details and pricing
   - Other users browse listings with filtering options
   - Purchase requests facilitate seller-buyer contact
   - All transactions logged for audit purposes

3. **Admin Dashboard**:
   - Real-time statistics and user management
   - Verification oversight and manual overrides
   - Marketplace moderation tools

## External Dependencies

### Required Python Packages
- `discord.py`: Discord API wrapper for bot functionality
- `python-dotenv`: Environment variable management
- `aiosqlite`: Async SQLite database operations
- `aiohttp`: HTTP client for Highrise API calls
- `pytz`: Timezone handling for timestamps

### External APIs
- **Highrise Web API**: User profile verification and data retrieval
  - Endpoint: `https://webapi.highrise.game/users`
  - Used for bio validation and user data fetching
  - Rate-limited to prevent API abuse

### Database
- **SQLite**: Local file-based database (`highrise_bot.db`)
- **Rationale**: Simple deployment, no external database server required
- **Considerations**: May need migration to PostgreSQL for high-scale usage
